## 1. LangChain Jev-as-a-Judge：Jev 作为"第三种评估器"的系统性证据

**来源**：[LangChain 官方博客文章](https://x.com/LangChain/status/2101454284927959080)（Daniel Shea & Seán Roche，2026-09-20）

前五轮一直把 Jev 定位成"分类/路由/闸门"，Language Chain 这轮补上了第四类能力：**Agent 评估器**。文章用一个固定的 Deep Agents agent + LangSmith dataset（5 个 weather requests），让 Jev、GPT-5.6 Luna、GPT-5.6 Terra、Claude Sonnet 4.6 各自对相同 agent 行为做 100 次重复评判，测量准确率（与人类 oracle 一致度）与方差（同一行为能否稳定给出同一个分数）。

**关键数据：**

| 指标 | Jev | Luna | Terra | Claude Sonnet 4.6 |
| --- | ---: | ---: | ---: | ---: |
| binary does_pass 与 oracle 一致 | **100%**（500/500） | 96.4% | 99.8% | 80.0% |
| quality 分数方差（越低越稳） | **0.0000149** | 433× 高 | 913× 高 | 92× 高 |
| 平均延迟 | **0.44s** | — | — | — |
| 单次成本 | **$0.00035** | — | — | — |
| 总成本（5 case × 100 rep × 2 signals） | $0.34 | — | — | $28.17 |

**三点必须注明：**

1. **方差低 ≠ 准确率高**。作者明说："a judge can still be consistently wrong."Jev 的胜出恰好是"又准又稳"的组合——这是实验设计优于单指标的地方。
2. **n=5 个 case 的窄实验**。作者自己标注"results are promising, but early"。
3. **为什么方差低是假说而非结论**：作者猜测是"Jev 决策优先架构 vs LLM 文本生成后映射"的差异，但明说"observational, not evidence"。

**对本仓库的意义**：这直接呼应了我们首轮 agent-control 的"独立评判器"方向——LangChain 证明 Jev 当评判器在**重复稳定性**上是全新量级。我们第三轮实测的重复稳定性（99.1% 决策一致率）与它同构，但 LangChain 给了外部对照。

## 2. biscuit 2.8 万请求实测：至今最全的 Jev 能力边界图

**来源**：[zenn.dev 文章](https://zenn.dev/biscuit/articles/typesafe-ai-jev-benchmark-2026-09)（2026-09-20），作者自地址 25,800 请求、$2.1

这是目前见到的最完整独立实测：3 个公开数据集（MASSIVE 60 意图、PAWS-X 同义判定、JSICK 含意+相关度），日英对照，8 并行，固定 `jev-1.13.0`。核心发现分五块：

### 2.1 击穿官方宣传的关键数字

| 官方主张 | 实测结果 |
| --- | --- |
| 1→500 问延迟"几乎不变" | 服务器侧 98ms→239ms（2.4 倍，不是不变，但 100 问仅 +50ms） |
| 各问题独立评估 | 输出偏移平均 0.004，与同一请求重复 10 次的固有抖动同量级——**独立成立** |
| 输入 token 只计 1 次 | 实测确认：400 条无关数据时 1 问与 500 问的差分完全相同（4,255 token）——**计费规则清楚** |
| 日语精度下降 | MASSIVE 83.2% vs 英 83.0%（**无差**）、JSICK 85.4/87.4（无差）、PAWS-X 70.2/82.6（**明确差 p<0.001**，但含表记揺れ因素） |
| 官方"数值弱" | **半对半错**：日付统一格式 100%、9 位大小 100%（好于预期）；3 位加法 70%（阈值调 0.99→100%）；50 元素计数上限 82%（真弱） |

### 2.2 置信度与其致命前提

- **过信是系统的**：返回概率 0.98–0.99 的回答，实际正确率只有 93–95%；JSICK 中 0.7–0.9 段实际只有 58–61%。**置信度只能用于排序，不能当真实概率**（与我们第三轮结论吻合，且扩大到日文/公开数据集）。
- **"conf≥0.9 → 自动处理"的前提是"输入必属某类"**：把正确答案从 60 选中拿掉，日语 24.0% / 英语 29.6% 仍以 conf≥0.9 自信选错。加 `none_of_the_above` 后约 6 成能正确表示"都不对"，但剩 4 成仍 conf 0.84 选错。**"答案不在全集"无法可靠表达**——这是客服分流里"无法归类"工单的硬风险。
- **Score 的 confidence 语义不同**：Score 高 confidence ≠ 误差小（0.7 以下组 MAE 0.48 反而优于 0.8–0.9 组 0.64）。因为 confidence 衡量概率集中度，而 Score 是期望值——"评级恰好落在刻度中间"也会低 confidence 但算得准。**Score 的 confidence 不能当 Choice 的 confidence 用**。

### 2.3 注入攻击的机制级新发现

文章把官方 model-jaggedness 的对抗性声明量化成四种条件对照（这是前几轮没有的）：

| 条件 | 攻击成功率（日 / 英） |
| --- | ---: |
| A 未加工 | 0% / 0% |
| B 攻击文追加到被引用字段 `utterance` | **23.2% / 9.0%** |
| C 无害文追加到 `utterance` | 0% / 0.2% |
| D 攻击文放未引用字段 `note` | 1.0% / 0.8% |

三个机制结论：
1. Jev **字面读**被引用字段，攻击指令若在该字段内会改变判定（日语更敏感：短输入占比较大，8 字以下 49.3% 被带偏）。
2. **不是"文本变多"导致的**（C 对照几乎 0%）。
3. **未引用字段几乎完全被忽略**（D ≈ 1%）——这在工程上反而是安全特性：**把不可信输入与可信指令隔离到不同字段，攻击面基本关闭**。

### 2.4 噪声数据与字段隔离

官方"大 state 充满无关细节精度下降"的警告，在**字段隔离**条件下不成立：20k token 无关记录放进 `unrelated_records`，被引用字段判定几乎不变（PAWS-X 70.7→70.0%、MASSIVE 81.3→84.0%）。**前提是问题明确引用目标字段**——这修正了我们第三轮"context rot 需要真正长状态"的判断：context rot 的触发条件不是 token 总量，而是**被引用字段内的内容腐化**。

### 2.5 工程注意事项（10 条，直接可用）

- 连接复用极其重要：日本 RTT 136ms，TLS1.2 每连接 415ms vs TLS1.3 280ms，Keep-Alive 下 1 问总往返 235ms（其中服务器 98ms）。**我们首轮 1.5s 端到端延迟的大部分是连接开销**——与第四轮"延迟分段"待办吻合。
- 空输入不报错且倾向自信分类：空 state 的 Choice 仍 conf 0.97–0.98 选"technical"。**必须在应用层校验输入**。
- 同一请求返值有 0.01–0.05 固有抖动，阈值不要设在精确边界。
- 选项加 `none_of_the_above` 是防御 OOD 的最便宜手段（non-zero 但有效）。
- 版本跟踪用响应体 `model` 字段（`jev-latest` → 响应 `jev-1.13.0`）。
- 25,800 次仅 1 次 503 重试、0 最终失败——**服务可用性至今无实质问题**。

## 3. JevBench v1.2.2：榜单大洗牌但真相微妙

**来源**：[benchmarkheaven.com/jev-models](https://benchmarkheaven.com/jev-models)（2026-09-20 抓取）

榜单从 v1.2（15 系统）扩到 **v1.2.2（21 系统 × 534 决策）**。最大变化是 **classifier.dev 以 84.8 登顶，把官方 Jev 挤到第二（75.3）**。

**必须写清楚的事实**：classifier.dev **不是独立模型**——榜单说明原文"classifier.dev runs Jev behind its own API, so it matches Jev on Intelligence（90.1 vs 90.4），leads on Speed（p50 0.39s vs 0.65s，德国服务器到我方）and on Cost（flat plan ~$0.0033/千决策 vs Jev 按 token $0.041/千决策）"。也就是说 **#1 是 Jev 的分发层优化**（flat 价 + 更快接入），不是模型能力超越。真正的信息量在于：

1. **开源复刻阵容成型**：SemIf 74.6 (#3)、djev/diffusion-gemma 74.3 (#4)、Laya 70.1 (#5)、jeff/GLiFormer 66.9 (#9)、OpenJev-DiffusionGemma 67.6 (#8)、openJev-Verdict (ModernBERT 151M) 66.1 (#11)、GLiNER2 52.9 (#18)。**"Jev 类"已经不是一个模型，而是一个赛道。**
2. **模型轴与成本轴分离**：Luna Intelligence 96.8 但综合 66.0（#12，成本分 28.2）；DeepSeek Calibration 96.7 但综合 58.1（#16）。几何均值设计就是"弱轴拖垮"，**校准/智能好但贵，在新基准里不划算**。
3. **Jev 的校准分 82.7 不是最高**（Luna 89.8、DeepSeek 96.7）——我们此前"Jev 校准真实优势"的说法需要细化：相对轻量 LLM 成立，相对强 LLM 不成立。
4. **方法论局限仍在**：自托管端点延迟 ×2 (+0.15s) 是"假设不是测量"；成本多为估计或 announce。

**与上一轮的延续**：JevBench v1.2 时 SemIf 与 Jev 差 0.7 分，现在（classifier.dev 走后）仍是 Jev 75.3 vs SemIf 74.6——**开源逼近没有扩大**，但也没有追平。选项顺序敏感性的方法论警告（上一轮 open-alternative-jev 72%→21%）仍是本仓库评测脚本的待办。

## 4. "2 天 6 克隆"：复刻路线分化

**来源**：[Kuman 帖](https://x.com/KUMAN_R/status/2101473262693994936)（翻译 Latent Space AINews 汇总）+ [ZHO_Kev 帖](https://x.com/ZHO_ZHO_ZHO/status/2101551314199335221)

因为 Jev 本体不公开，社区靠"推测内部结构"做出了 6 种架构不同的复刻：

| 克隆 | 架构 | 备注 |
| --- | --- | --- |
| Laya | ModernBERT 系编码器 421M + PPO | 已上 JevBench #5，★1.8k |
| DiffusionGemmaJev | 扩散模型再现 | `djev` 已上 JevBench #4（74.3，MAISA） |
| Bespoke Nimble | Qwen3.5-9B LoRA | 自评 90%（原版 93%） |
| SemIf（旧 OpenJev） | Qwen3.5 + 3 类 NLI 分类器 | 4B 与 35B，JevBench #3 |
| Jevlike | 嵌入 40KB 轻量注意力 | — |
| Kev-0.5B | 0.5B LoRA | MacBook Pro 可跑 |

**两个值得说的**：
- **Kev-0.5B 的架构描述最有价值**（ZHO 帖）：shared state → isolated parallel question branches → learned pointer readout → probability distribution，一次 prefill 并行多个"互不泄漏"的判断、不做自回归解码——这是社区对 Jev 并行多问机制的工程化理解。
- 结合 JevBench，**复刻已经形成"编码器型 vs 解码器型 vs 扩散型"三条路线**，且 Laya（编码器，成本分 86.2 全场最高）与 SemIf（解码器，准确率最接近）各有取舍。这进一步支持第四轮"护城河在数据配方与分发而非架构"的判断。

## 5. yibie 的 Jev vs Laya 级联：最贴近本仓库的对照实验

**来源**：[yibie 文章帖](https://x.com/yibie/status/2101553680889598094) + 仓库 [laya-jev-lab](https://github.com/yibie/laya-jev-lab)（已核实：50 commits 前 1 commit，40 基准、20 脚本、结果全公开，M4 Max / MLX）

这是本轮与我们统计学上最像的实验：**同一批 40 条中文客服消息、同一套标准、同一问题措辞**，Jev（云端）vs Laya（本地 7.6ms），再拼级联。

**结果：**

| | 准确率 | 平均置信度 | 延迟 |
| --- | ---: | ---: | ---: |
| 纯 Jev | 31/40 = 78% | 0.88 | 588ms |
| 纯 Laya | 23/40 = 57% | 0.71 | 7.6ms |
| 级联（阈值 0.60） | **78%**（等同 Jev） | — | **327ms（快 1.8×）** |

难度拆解：清晰题 Jev 100% / Laya 75%；模糊题 70%/60%；边界题（"你好""???"）40%/20%——边界题两家都差，属"问题本身没有答案"。

**三条教训与我们直接相关：**

1. **单独测 Laya 时"conf≥0.7 时 86-100%"是假象** ——把两家放一起才发现 0.70–0.80 档只有 50%。**小样本置信度曲线不可靠**（我们第三轮同样警告过）。
2. **"信息越少越自信"**：Laya 对"退款。"给 0.97 且对；对"我要退款，东西还没发货"给 0.92 却错（判 logistics，Jev 判 billing 0.98 正确）。第二个信号覆盖第一个，置信度毫不反映冲突。
3. **级联拦不住"自信地错"**：17 个错判，级联拦下 14 个，漏 3 个——漏的都是高置信错判。**换模型不解决"自信地错"，只有人工定义清楚问题能。**

**与本仓库的互证**：yibie 的级联设计（Laya 本地 + Jev 升级）与我们第三轮"置信度升级闸门"是**同一个机制的两端**——他做的是"本地廉价 + 云端准确的横向升级"，我们做的是"Jev 首过 + 强 LLM 纵向升级"。两者共用同一发现：**置信度能拦住"知道自己不确定"的错，拦不住"自信地错"**。

## 6. 新的一手使用案例

### 6.1 GTM 工作流（saunakdg，100+ 实验综述）

核心架构："便宜决策上游、昂贵分析下游"，例子含：Matthew Berman 724 ads 40s/$0.09（23,680 判断）；723 ads × 30 personas = 21,690 判断 $0.22；Ian Nuttall 3,282 帖 8 问 8m34s/$0.1282（发现 how-to 帖中位赞 150 vs 整体 44）；700 leads 40s/$0.09；Piyush Patel Account Grader 1,000→100 问题匹配；AIsa/Rafael 150 tweets→750 决策→79 值得回复 $0.007。**作者明确标注这些是 demo receipts 非生产经济性**——正合我们一贯口径。

### 6.2 游戏/实时控制（全部作者自报）

- **Minecraft 击败末影龙**（[rronak_](https://x.com/rronak_/status/2101544156757950697)，开源 `rmalde/minecraft-agent`）：Jev 控制玩家（WASD/空格/点击/鼠标），Astra 异步规划；失败时 Astra 把技能写为 mjs 文件持续学习，8 分 43 秒速通，Jev $0.01 + Astra $0.96。**Jev 控制器 + LLM 规划者 + 技能文件演化**是新形态。
- **自动驾驶战术层**（[SuSu](https://x.com/NFT_Chen/status/2101234910677926117)）：代码管感知+硬安全（reflex 永远优先），Jev 3Hz 战术判断（直行/绕行/停车等/倒车）；41 次调用 $0.00244、81 次 <0.5 美分；延迟 170–260ms。
- **地铁跑酷 50 局**（AI Will <1 美分）、**恐龙跳跃人机对战**（libapi，Netlify 真调 API）、**鲸鱼城市决策游戏**（gokaygokay：Astra 设计世界 + Jev 选动作 + H3 Max 每轮转视频，5 分钟 264 片段）。
- **电车难题**（AI Will）：100 次中 99% 概率选择拉杆牺牲 1 救 5 —— **价值判断的稳定功利偏向**，值得记入"Jev 会系统性偏向什么"清单。

## 9. 本轮之后的判断变化

1. **"Jev 当评估器"已经从猜想变成主流背书。** LangChain 官方实验证明：在 agent eval 的窄任务上，Jev 的重复一致性（方差低 92–913 倍）、准确率（500/500）和成本（$0.34 vs $28.17）是三维全胜。**稳定性——而不是准确率——是 Jev 相对 LLM 最有区分度的资产。**
2. **"概率/置信度可信"必须加两个限定。** 一是绝对值过信（0.98–0.99 实际 93–95%），二是 Score 的 confidence 与 Choice 的 confidence 语义不同。**置信度是排序信号，不是概率估计。**
3. **字段隔离是防注入的工程答案。** Jev 字面读被引用字段、忽略未引用字段（≈1%）——把不可信输入与指令分字段放，攻击面关闭。"prompt injection 无害"（第四轮 clay 0/12）需要按"是否在被引用字段内"重新表述。
4. **OOD 是置信度闸门的隐藏前提。** "答案不在全集"仍会以高置信度自信选错（24–29.6%）；`none_of_the_above` 只能缓解不能消除。**客服分流的"无法归类"必须显式建模。**
5. **语境评分的伦理偏向需要关注。** 电车难题 99% 拉杆是价值设定的体现，值得与"Jev 适合/不适合哪些决策"并列记录。
6. **生态进入"评测期"而非"构建期"。** JevBench 榜单 3 天 15→21 系统、2 天 6 克隆、LangChain/biscuit 双独立测——Jev 正在被当作基础设施评测，而不是被当作新奇玩具。

## 10. 下一轮优先级
