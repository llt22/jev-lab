# Jev 首轮验证报告

> 验证日期：2026 年 9 月 18 日
> 模型：`jev-1.13.0`
> 目标：验证 Jev 作为客服工单结构化决策层的质量、稳定性、延迟、成本和多问题并行价值。

## 阶段性结论

首轮实测支持以下判断：

1. **Jev 是可用的工程组件，不是只有演示效果。** 记录的 120 次 API 请求全部成功，响应结构稳定，没有缺失问题或非法概率。
2. **同一输入下的结果非常稳定。** 36 条样例重复三轮，Category 和三个 Noul 的二值决策均为 100% 一致。
3. **多问题 fan-out 是明确优势。** 同一状态从 1 个增加到 20 个 Noul 问题，端到端延迟没有随问题数线性增长，P50 仍约 1.4 秒。
4. **成本很低。** 三轮客服基准共 108 次请求、104,835 输入 token，按当前每百万输入 token 0.042 美元估算约 0.0044 美元。
5. **当前不能证明 Jev 比简单方案更智能。** 一个查看过任务定义的关键词基线在类别分类上得到 97.2%，高于 Jev 按原始标签计算的 91.7%，说明 pilot 数据过于直白。
6. **当前端到端延迟约 1.5 秒，不是社区常见宣传中的 70–500ms。** 这可能包含网络、排队和 API 网关时间，但对真实应用而言端到端延迟才是需要规划的指标。

因此，Jev 的**产品形态、稳定性、成本和并行计算价值已经得到初步支持**；其相对开源小模型、传统分类器和通用 LLM 的质量优势仍需第二阶段验证。

## 测试设计

### 客服路由数据集

首轮数据集包含 36 条英文合成工单，由 12 个业务场景各生成 3 个同义改写：

- Wi-Fi 阻塞近期会议
- 信息不足的 VPN 故障
- 密码重置链接失效
- 工资发放管理员被锁定
- 重复扣款
- 套餐价格咨询
- 活跃账号接管
- 已确认安全告警为本人操作
- CSV 导入崩溃
- 深色主题功能请求
- 完全模糊的故障描述
- 有明确时限的退款延迟

每条工单同时评估五个问题：

| 问题 | 类型 | 输出 |
| --- | --- | --- |
| 主要业务类别 | Choice | network/account/billing/security/product/other |
| 是否紧急 | Noul | 0–1 |
| 是否需要人工 | Noul | 0–1 |
| 是否缺少必要信息 | Noul | 0–1 |
| 用户表达的挫败程度 | Score | 0–2 |

数据和问题定义位于：

- [`evals/support-routing-v1.jsonl`](../evals/support-routing-v1.jsonl)
- [`evals/support-routing-v1.questions.json`](../evals/support-routing-v1.questions.json)

### 评测指标

- Choice Accuracy、Macro F1、Brier、NLL 和 ECE
- Noul Accuracy、Brier、ECE 和置信度覆盖率
- Score MAE、四舍五入准确率和 Multiclass Brier
- 同义改写组一致率
- 重复运行决策稳定性和概率漂移
- P50/P95 端到端延迟
- 输入、输出 token 和估算成本

## 首轮质量结果

三轮运行的总体质量指标几乎完全相同：

| 指标 | 第 1 轮 | 第 2 轮 | 第 3 轮 |
| --- | ---: | ---: | ---: |
| Category Accuracy | 91.7% | 91.7% | 91.7% |
| Category Macro F1 | 0.908 | 0.908 | 0.908 |
| Category 组一致率 | 91.7% | 91.7% | 91.7% |
| Urgent Accuracy | 100% | 100% | 100% |
| Needs Human Accuracy | 100% | 100% | 100% |
| Missing Info Accuracy | 97.2% | 97.2% | 97.2% |
| Frustration MAE | 0.212 | 0.211 | 0.211 |

第一轮详细校准结果：

| 判断 | Brier | ECE |
| --- | ---: | ---: |
| Category | 0.095 | 0.054，使用最高类别概率 |
| Urgent | 0.009 | 0.080 |
| Needs Human | 0.033 | 0.147 |
| Missing Info | 0.091 | 0.247 |

样本量只有 36 条，ECE 对分箱非常敏感，不能据此声称概率已经充分校准。`missing_info` 的 ECE 最高，说明即使二值准确率较高，其概率强度仍不适合直接当作真实正确率。

### 置信度门控

Category 使用官方 `confidence` 门控时：

| Confidence 阈值 | 覆盖率 | 覆盖样本准确率 |
| ---: | ---: | ---: |
| 0.50 | 94.4% | 97.1% |
| 0.70 | 91.7% | 100% |
| 0.85 | 88.9% | 100% |

所有严格标签下的 Category 错误都出现在低 confidence 样例中，说明 confidence 在这组数据上具有一定的拒答价值。但官方文档也明确说明，confidence 是概率分布集中程度，不等于答对概率，阈值仍需使用真实业务数据校准。

## 标注审计

严格标签下的三个 Category 错误全部来自同一组：

```text
安全告警已经确认是本人操作，实际请求是关闭或减少安全通知。
```

原始标签将其标为 `security`，但问题规则要求按“客户需要处理的主要问题”分类。模型分别选择了 `account`、`product`、`product`，其中后两项可能比原标签更符合实际诉求。

如果统一将这组标为 `product`，Jev 会命中其中 2/3，Category Accuracy 将从 91.7% 变为 97.2%。由于这是看到结果后的标签审计，本报告保留原始严格分数，不使用调整后的结果作为正式成绩。

情绪标签也存在类似问题：部分样例因为事件严重被标为 1，但文本语气本身平静，和题目“只判断表达出的挫败程度”不一致。这说明第二阶段数据必须进行盲标和标签复核。

## 重复运行稳定性

相同 36 条输入连续运行三轮：

| 输出 | 决策一致率 | 平均概率/分数极差 | 最大极差 |
| --- | ---: | ---: | ---: |
| Category Choice | 100% | 不适用 | 无翻转 |
| Urgent Noul | 100% | 0.0042 | 0.0200 |
| Needs Human Noul | 100% | 0.0097 | 0.0300 |
| Missing Info Noul | 100% | 0.0181 | 0.0400 |
| Frustration Score | 不适用 | 0.0094 | 0.0500 |

这表明 `jev-1.13.0` 在同一输入下具有很强的可重复性。该结果不覆盖模型版本升级、输入改写、长上下文和并发压力下的稳定性。

详细结果见 [`artifacts/support-routing-v1-repeat-stability-2026-09-18.md`](../artifacts/support-routing-v1-repeat-stability-2026-09-18.md)。

## 延迟与可靠性

三轮客服基准共记录 108 次请求：

| 指标 | 结果 |
| --- | ---: |
| API 错误 | 0/108 |
| 平均延迟 | 1531 ms |
| P50 | 1475 ms |
| P95 | 1902 ms |
| 最大值 | 2426 ms |

这个结果明显高于社区常见的亚秒级宣传。可能原因包括客户端到服务端网络、网关、排队和冷启动。对在线业务进行容量规划时，应以本地到 API 的端到端 P95 为准，而不是只采用模型服务端推理时间。

尚未验证：

- 并发请求吞吐量
- 429/529 下的恢复行为
- 不同地区网络延迟
- 长上下文下的延迟和准确率
- 生产时段的尾延迟

## 成本

官方文档在 2026 年 9 月 18 日列出的 `jev-1.13.0` 价格为每百万输入 token 0.042 美元，输出 token 免费。

三轮客服基准合计：

| 项目 | 数值 |
| --- | ---: |
| 请求数 | 108 |
| 输入 token | 104,835 |
| 输出 token | 13,608 |
| 估算输入成本 | 0.004403 美元 |
| 平均单次输入成本 | 约 0.000041 美元 |

成本优势成立，但真实生产成本仍取决于状态长度。短工单的成本不能外推到包含完整会话、知识库片段或大型 Agent 日志的请求。

## Fan-out 测试

使用相同短状态，分别在一次请求中提交 1、5、10、20 个 Noul 问题，每组重复三次：

| 问题数 | 平均延迟 | P50 | 平均输入 token | 平均输出 token | 估算单次成本 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1756 ms | 1463 ms | 371 | 22 | $0.000016 |
| 5 | 1425 ms | 1418 ms | 424 | 94 | $0.000018 |
| 10 | 1368 ms | 1379 ms | 493 | 184 | $0.000021 |
| 20 | 1417 ms | 1424 ms | 639 | 364 | $0.000027 |

在这个小样本中，从 1 个增加到 20 个问题没有增加可观察的端到端延迟，输入成本仅小幅增长。这是 Jev 当前最有说服力的实测价值：**同一状态可以低成本并行获取多个独立判断。**

1 问题组的平均延迟受一次 2466ms 请求影响，因此不能解读为问题越多反而越快。更合理的结论是 1–20 个短 Noul 问题的延迟差异被网络和服务波动覆盖。

详细结果见 [`artifacts/fanout-jev-1.13.0-2026-09-18.md`](../artifacts/fanout-jev-1.13.0-2026-09-18.md)。

## 关键词基线

为了检查数据集是否过于简单，编写了一个透明的关键词规则基线。它在查看任务定义和测试样例后实现，因此不是与 Jev 公平竞争的模型，只是难度 sanity check。

| 指标 | Jev | 关键词基线 |
| --- | ---: | ---: |
| Category Accuracy | 91.7% | 97.2% |
| Category Macro F1 | 0.908 | 0.966 |
| Urgent Accuracy | 100% | 94.4% |
| Needs Human Accuracy | 100% | 97.2% |
| Missing Info Accuracy | 97.2% | 100% |
| Frustration MAE | 0.212 | 0.401 |
| Frustration 四舍五入准确率 | 83.3% | 61.1% |

这说明：

- 当前类别样例包含明显关键词，不能证明 Jev 的语义分类优势。
- Jev 在否定、紧急度、人工升级和情绪程度上表现更好，但测试规模不足。
- 下一版必须加入无法靠单个关键词解决的最小对照、冲突证据和真实工单。

## Agent 控制面三项小样本验证

在首轮客服分类之后，又针对案例站中最值得继续验证的三个方向构造了独立小样本：上下文过滤、代码路径语义寻路和模型路由。固定使用 `jev-1.13.0`，三轮共完成 105 次 API 请求，其中 102 次首轮成功、3 次重试后成功，没有最终失败。

### 结果摘要

| 方向 | Jev 结果 | 对照结果 | 初步判断 |
| --- | ---: | ---: | --- |
| 上下文过滤 | 关键内容召回率 100%，危险误删 0；安全压缩率 6.3%–6.8% | 只保留最近两项的关键召回率 27.3%，危险误删 16 项 | 语义判断明显优于纯时间窗口，但当前更偏保守筛选 |
| 语义寻路 | 三轮 Top-1 均为 100% | 词法重叠基线 75% | 在 5 个候选路径中选择第一跳有明显信号 |
| 模型路由 | 三轮准确率均为 93.3%，错误降级率 6.7% | 数据适配后的关键词规则为 100% | 能区分明显难度，但没有胜过简单规则 |

上下文数据包含 8 个编码场景和 40 个工具产物。标签下的理论最大安全压缩率只有 6.9%，因为三个仍需保留的截图占据了大部分字符；Jev 实际取得 6.3%–6.8%，三轮均完整保留所有关键内容。唯一发生重复运行翻转的是一个已经无人调用的旧分页实现，其保留概率为 `0.49`、`0.51`、`0.49`。这说明 `0.5` 附近不能作为不可逆删除依据，更适合进入可恢复存根或灰区队列。

语义寻路包含 12 个任务，每个任务从 5 个候选路径中选择最应该先查看的文件。Jev 三轮均为 12/12，词法基线在 refresh token rotation、数据库 deadlock retry 和 CSV row validation 上失败。这个结果支持用 Jev 做候选重排，但候选数量很少、路径名称具有语义，尚不能外推到大型仓库的完整搜索。

模型路由包含 15 个编码任务，目标是选择最低够用的 `small_local`、`fast_general` 或 `strong_reasoning`。Jev 三轮都把一个已有复现测试的局部 off-by-one 修复从 `fast_general` 降到 `small_local`，其他任务全部命中。该结果说明 Jev 能稳定区分明显的简单任务和高风险跨系统任务，但中间难度边界仍需通过下游模型真实执行来定义，不能只依赖人工标签。

三轮累计输入 58,602 token、输出 6,354 token；所有请求平均端到端延迟约 1501ms，P50 约 1423ms，最大值约 5172ms。该延迟再次说明 Jev 适合按任务或批次做控制判断，不适合放在每个极细粒度同步步骤中。

### 当前结论

- **最值得优先继续做的是语义寻路。** 当前信号最强，也最容易用真实仓库的已知文件定位任务扩大验证。
- **上下文过滤必须采用可恢复设计。** 当前没有危险误删，但边界概率确实会翻转，不能把一次低于 `0.5` 当作永久删除许可。
- **模型路由有用，但价值尚未成立。** 它稳定、便宜，却没有胜过针对本数据编写的规则；下一步必须实际调用不同等级模型并比较任务成功率与总成本。

## 当前能确认的价值

### 已得到支持

- 类型化 API 稳定，错误可观察。
- 同一输入的输出高度可重复。
- 多问题共享状态的 fan-out 有明显工程和成本价值。
- 短文本多维判断成本非常低。
- confidence 可以帮助识别部分模糊 Choice，但必须重新校准阈值。

### 尚未得到支持

- 比开源小模型或传统分类器更高的任务质量。
- 官方概率在真实业务分布上已经校准。
- 社区宣传的 70–500ms 端到端延迟。
- 长上下文、中文、分布漂移和对抗输入下的稳定性。
- 高并发生产流量下的可靠性。
- 在高风险自动执行中可以不经独立验证直接使用。

## 第二阶段计划

进入真实选型前，需要完成：

1. 收集 300–1000 条匿名真实工单，按时间切分训练/校准/测试集。
2. 至少两名标注者盲标，记录分歧并形成明确标签手册。
3. 加入最小对照：只改变否定、时限、主诉或一个关键事实。
4. 加入长上下文、无关内容、冲突证据、提示注入和类别外输入。
5. 单独测试中文及中英混合工单；官方说明英语是主要训练语言。
6. 比较传统分类器、开源小模型零样本、领域微调小模型和通用 LLM。
7. 使用 Brier、ECE 和 reliability diagram 在独立校准集上选择阈值。
8. 固定 `jev-1.13.0` 进行评测，不直接依赖会移动的 `jev-latest`。
9. 测试 1k、8k、16k、32k 状态长度，以及 10–100 并发下的 P95/P99。
10. 根据真实自动处理收益、人工节省和误判成本计算业务 ROI。

只有完成这些步骤，才能判断 Jev 的“真正价值”是模型能力领先，还是主要来自优秀的接口、推理优化和产品化。
